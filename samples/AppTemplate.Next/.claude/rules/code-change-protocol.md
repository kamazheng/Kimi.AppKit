# 改码强制协议(Code Change Protocol)

> AI 在修改任何**业务代码**前,必须按此流程执行。这是强制动作,不是建议。
> 目的:先理解上下文与约束,再动手,避免破坏跨模块不变量。

## 修改前(必做)

1. **定位业务位置**:读目标文件的文件头导航卡片(上游→本服务→下游)。不清楚就先读 `CONTEXT.md` 找到它在系统地图中的位置。
2. **查硬约束**:对照 `domain-constraints.md`,确认本次改动会不会触碰任何已声明的约束(数据完整性 / 状态机 / 业务规则 / 权限 / 并发)。
3. **评估副作用**:列出本次改动会级联影响的实体/服务/接口。涉及不可逆操作(删除、状态跃迁)时,显式确认。
4. **查决策记录**:若改动涉及既有架构选择,先翻 `ADR/` 确认当初为什么这样设计,避免无意推翻。

## 修改中

- 遵循 `comment-conventions.md`:动到关键业务方法时补/更新方法级约束标注;在"不能改的原因"处留 `⚠️` 陷阱警告。
- 遵守文件行数约束(≤ 400 行硬上限,300 行预警),超限先重构再加码。

## 修改后(必做)

1. **同步文档**:若改动引入新实体/新流程/新约束 → 同步更新 `CONTEXT.md` 与 `domain-constraints.md`。若做了架构决策 → 追加一条 ADR。
2. **验证**:运行相关测试 / 跑起来观察行为。失败如实报告。

## 本项目的追加检查项（**强制**）

### 修改前 · 第 0 步：查 AppKit

⚠️ **在做上面任何一步之前**，先按 `.claude/rules/appkit-api-map.md` 查一遍
「这件事包里是不是已经有实现」。那张表是强制的——表内列出的能力禁止自己写一套。

表里没有时，按 `.claude/rules/appkit-consumption.md` 的「正确的查法」再确认一遍
（只 grep `public static class` 会漏掉接口+实现形态；只查一个包会漏；
按方法名统计会把不同类的同名方法混成一个）。

### 修改后 · 验证不能只看构建与测试

以下事故全部发生在「构建 0 告警、测试全绿」的情况下：

| 事故 | 靠什么才发现 |
|---|---|
| WASM 起不来 | 截图 |
| 字体被覆盖 | 截图（`document.fonts` 显示 loaded） |
| 静态资源被授权拦成 HTML | 浏览器 console |
| 管理页「新增」点了没反应 | **实际点击**（页面渲染完全正常） |

**每个 UI 改动必须**：跑起来 → 亮/暗截图 → console 0 错误 → **实际操作一遍功能**。

### 修改后 · 数据模型改动

- 两套迁移都要重新生成（`KMoldApp.Migrations.Npgsql` 与 `.SqlServer`）。
- 两个 provider 都要跑一次。
- 改枚举成员必须生成迁移——CHECK 约束把取值范围焊进了数据库层。
