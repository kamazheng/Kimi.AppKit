# 代码注释规范(结构化分层)

> 不追求"完整注释",只在关键位置写关键信息。**不写 WHAT(代码已表达),只写 WHY 与 WHERE。** 注释语言:中文。
> 下方示例为 C# 风格;`/init-context` 生成时请按项目主语言替换注释语法(JSDoc / docstring / GoDoc 等)。

## 层 1:文件头导航卡片(Service 类、重要实体类必须有)

```csharp
/// <summary>
/// [服务名] — [一句话职责]
/// </summary>
/// <remarks>
/// 【业务位置】[上游] → ★本服务★ → [下游]
/// 【上游依赖】[依赖的服务和条件]
/// 【下游影响】[创建/修改/删除了哪些实体]
/// 【关键约束】见 .claude/rules/domain-constraints.md #[相关章节]
/// </remarks>
```

## 层 2:方法级约束标注(关键业务方法必须有)

只标前置条件、副作用、不可逆操作,不解释代码逻辑:

```csharp
/// <summary>[方法功能]</summary>
/// <remarks>
/// 【前置条件】[必须满足的状态/条件]
/// 【副作用】[会级联创建/修改/删除什么]
/// 【不可逆】[执行后哪些操作不再可能](如有)
/// </remarks>
```

## 层 3:代码内陷阱警告(只在"不能改的原因"和"易踩坑处")

```csharp
// ⚠️ 必须先删 子表 再删 父表,FK 约束不允许级联
// ⚠️ 此处用 Restrict 而非 Cascade,防止误删关联执行记录
```

## 核心原则

- **不写 WHAT** —— 好命名胜过注释。
- **只写 WHY** —— 为什么这样、为什么不能改、隐藏约束。
- **只写 WHERE** —— 业务位置、上下游依赖、关联文档指引。
